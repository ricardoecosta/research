## Tactics and playbook steps

**Put the full app workflow in one build prompt** (product)
1. Describe the target user flow, not only the interface.
2. Include onboarding, dashboard, core actions, editable AI results, progress views, storage, loading states, and error handling.
3. Inspect the generated app by completing onboarding and trying a representative meal entry.
> "I am including everything in just one prompt here because I really do want to test how Argon understands the design, the tracking features, and the AI functionality, how all of that should work together from the beginning, rather than having to introduce every feature separately." — Narrator (~6:43)

**Make AI-generated nutrition estimates editable** (product)
1. Let users review and edit estimated foods and portions before saving.
2. Check that saving a meal updates calorie totals and macro bars.
3. Inspect weekly progress and AI suggestions against the user's remaining targets.
> "Now, since these are AI-generated estimates, it is important that users can make corrections whenever it's needed." — Narrator (~8:03)

**Review a source document before drafting from it** (operations)
1. Upload the complete source PDF and ask for a section-by-section assessment.
2. Request issues with page references and severity, including inconsistencies in numbers, dates, and technical claims.
3. Compare the findings with the PDF before asking for documentation in the same conversation.
4. Ask the model to flag conflicting information instead of resolving it through assumptions.
> "And since Argon already has the document in context, all of it, we can continue working without uploading anything again." — Narrator (~11:06)

**Give a coding agent a complete task and a run condition** (operations)
1. Specify the stack, project constraints, features, and expected user experience.
2. Ask the agent to install dependencies and start the development server.
3. Set a concrete completion condition: fix errors until the project runs.
4. Run the result and inspect both functionality and the agent's error handling.
> "And the final part of our prompt here is particularly important because we're asking Argon to install the dependencies, to start the development server, and then fix any errors it encounters until the game runs properly." — Narrator (~15:05)

**Keep API keys out of public code** (legal)
1. Store the Gemini API key in an environment variable.
2. Do not place the key directly in public code.
3. Enable billing only when ready to make API requests and monitor usage.
> "So, store it in an environment variable rather than putting it directly into public code, because anyone who gets access to it could potentially generate charges on your account." — Narrator (~17:55)

**Start with a beginner-friendly interface before moving to agents** (mindset)
1. Try Argon in Google AI Studio or the Gemini app.
2. Experiment with a few projects and learn what the model handles well.
3. Move to API integrations or coding agents when there is a specific task that needs them.
> "For complete beginners, I would recommend getting familiar with Argon through Google AI Studio or the Gemini app first." — Narrator (~20:02)

**Use reasoning depth appropriate to the task** (operations)
1. Choose low, medium, or high reasoning based on how complicated the task is.
2. Treat the setting as a task-level choice rather than a universal setting.
> "Now, there are three thinking levels to choose from here, low, medium, and high, depending on how complicated your task actually is." — Narrator (~4:08)

## Lessons

- *validation_testing*: Evaluate a model on a substantial multi-step task, not only on a single answer to a prompt.
- *offer_design*: Write prompts that describe the complete user flow and how the parts should work together.
- *operations*: Treat AI-generated numbers and technical findings as drafts that need checking.
- *operations*: Use the source document as the reference when reviewing and drafting technical material.
- *automation_ai*: Give coding agents an end condition, such as a running development server, and then inspect the result.
- *mindset_execution*: Choose a tool that fits the task and start with a simpler interface while learning.
- *legal_risk*: Keep API credentials out of public code and account for usage-based charges.
- *automation_ai*: Select reasoning depth based on task complexity.
