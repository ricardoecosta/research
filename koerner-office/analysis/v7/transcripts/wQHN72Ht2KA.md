## Tactics and playbook steps

**Compare builders with identical client-style prompts** (validation_testing)
1. Give each platform the same brief and requirements.
2. Test a local business website, a functional web app, and a lead generation landing page.
3. Record build time, errors, functionality, design quality, and correction prompts.
4. Judge whether the output is usable for a client, not just whether it looks finished.
> "And we're not just judging on looks, build speed, errors, working functionality, native AI, authentication, publishing, pricing, and all the hidden costs nobody mentions until the invoice is due." — Host (~0:49)

**Use a structured brief for local business sites** (product)
1. Specify the business and the desired visual style.
2. List the required hero, services, about, testimonials, contact information, and booking form.
3. Check that the generated site includes each requested section and is presentable to a client.
> "include a hero section with a bold headline and a book now call to action, a services section showing three wash packages with pricing, an about section, a testimonial section with three customer reviews, and a contact section with location, hours, and a booking form." — Host (~2:44)

**Test apps end to end before delivery** (operations)
1. Test the primary feature with a real input.
2. Check that the report corresponds to that input rather than placeholder or fake output.
3. Verify authentication and saved history.
4. Include the time and effort required for corrections in the delivery plan.
> "A static website can look good even if nothing is happening behind the scenes. A web app has to actually work." — Host (~7:39)

**Build landing pages toward one conversion action** (offer_design)
1. Use the hero to state the value and present a clear call to action.
2. Explain the features and how the product works.
3. Add testimonials to establish trust.
4. Make the lead capture form the natural next step.
> "A good landing page should build momentum from the hero down, explain the value quickly, show how the product works, add some trust, and then make the email capture form feel like the natural next step." — Host (~12:28)

**Compare the full cost of delivering client projects** (finance_unit_economics)
1. Compare subscription prices and included credits.
2. Check whether AI, hosting, publishing, authentication, and database features are included.
3. Identify external API keys and services that add costs beyond the builder subscription.
4. Consider whether usage-based billing makes project costs hard to predict.
> "Hosting and publishing and authentication, database access, AI features, credit limits, and hidden costs all matter here" — Host (~16:11)

**Choose a builder based on the work being sold** (product)
1. For front-end projects, check whether the builder produces fast, reliable websites and landing pages.
2. For client apps, test native AI and other core features without assuming a visual demo works.
3. Compare correction effort and recurring costs before choosing a platform for regular client work.
> "If your offer is just front-end work, fine. Bolt can work for you. If you want to sell smarter web apps, it hits limits pretty quickly." — Host (~21:48)

## Lessons

- *validation_testing*: Test the core feature with real inputs; a polished interface is not proof that the product works.
- *finance_unit_economics*: Time spent fixing generated output reduces the profit from a freelance project.
- *pricing*: A client tool with accounts, stored data, and working features can support a higher project fee than a basic site, according to the host.
- *automation_ai*: For apps that depend on AI, native integration can reduce setup friction, but the feature still needs a real end-to-end test.
- *finance_unit_economics*: Compare the full cost of a tool, including API keys, hosting, credits, and separate database services, rather than relying on the subscription price alone.
- *offer_design*: A landing page should explain value, demonstrate how the offer works, establish trust, and lead visitors toward one clear action.
- *niche_selection*: Select a builder for the type of client work you plan to sell; performance on static pages does not guarantee good app results.
- *validation_testing*: A fair tool comparison uses the same prompts and requirements across platforms and evaluates functionality, speed, errors, and cost.

## Warnings and mistakes

- A website that looks complete may have fake or non-working functionality. The host found the audit app returned data for a different site.
- Some builders require external API keys before the central app feature works, and those external services can add costs.
- Correction prompts, retries, and errors can make delivery risky for a freelancer working to a client deadline.
- Usage-based credits, hosting, and AI charges can make a builder's real costs less predictable than its headline subscription price.
- The host promotes a free master class that normally costs $499, creating a promotional conflict in the video.
