## Tactics and playbook steps

**Controlled multi-prompt benchmark for comparing AI builders** (product)
1. Pick one realistic app (a client CRM) and write three sequential prompts: base build, added features, polish/responsive
2. Give every platform identical prompts in identical order with no extra hints
3. Do not fix problems midway; evaluate the state after each prompt and allow limited re-prompts only at the end
4. Score on speed, learning curve, output quality, flexibility and value for money (20 points each)
5. Specifically check whether new prompts break features that already worked
> "every platform gets the same three instructions in the same order. No rewritten prompt for one platform, no extra hints, and no special workaround" — Mikey (~4:35)

**Staged CRM prompt sequence for AI app builders** (product)
1. Prompt 1: client list (name, company, email, phone, status), add-client form, summary cards, sidebar nav, modern design
2. Prompt 2: timestamped notes, follow-up dates, three statuses, upcoming 7-day follow-ups on dashboard
3. Prompt 3: real-time search, responsive down to 375px, spacing cleanup, empty states, explicitly preserve existing functionality
> "We'll add real-time client search, make the app responsive down to a 375-pixel mobile screen, clean up spacing and visual inconsistencies." — Mikey (~6:06)

## Lessons

- *validation_testing*: Judge AI builders by iterative stability (does prompt 3 break prompt 1?), not by first-prompt demos.
- *validation_testing*: Use a fixed, repeatable benchmark (same prompts, same rules, limited retries) to compare tools fairly before committing.
- *offer_design*: Core-function reliability outweighs polish: a beautiful app with a broken add-client function is unusable as a CRM.
- *automation_ai*: For an agent-driven build workflow, prefer tools that need no recovery steps or babysitting; low intervention per iteration is the key automation metric.
- *other*: Match the tool to the priority: Replit for distinctive design, Bolt for predictability, Base44 for speed and completeness.
- *finance_unit_economics*: Credit-based pricing makes debugging cost real money; factor re-prompt/fix cost into value-for-money.
- *operations*: Always explicitly instruct the AI builder not to change existing functionality when requesting polish or new features.

## Warnings and mistakes

- A strong first prompt output says little about stability; later prompts can break previously working core features (Lovable's add-client error persisted to the end).
- Credit-based AI builders can become costly when you must spend credits fixing features that broke during the build.
- Test is a single small CRM app with one run per platform and subjective scoring by a creator who sells Base44 training, so results may not generalise.
